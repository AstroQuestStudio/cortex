Handling retries in HTTP clients

By Dana · March 2024

Retries make clients resilient, but a naive loop can turn a small outage into a big one. This article walks through a safe policy.

Why back off

When a server is overloaded, immediate retries add load. Exponential backoff spreads the load over time.

  1. Wait base * 2^attempt milliseconds.
  2. Add random jitter to avoid thundering herds.
  3. Stop after a fixed number of attempts.

A minimal implementation

import random, time

def retry(fn, attempts=5, base=0.1):
    for i in range(attempts):
        try:
            return fn()
        except IOError:
            time.sleep(base * 2 ** i + random.random() * 0.05)
    raise RuntimeError("giving up")

Retry only idempotent requests, or make the operation idempotent with a key.

Which errors to retry

Conclusion

Keep the policy simple and observable.
